# 영수증 인식 단독 테스트 (U-06)

기능명세서 **U-06 영수증 자동 정리**를 앱에 붙이기 전에, "사진을 넣으면 필요한 값이 얼마나 정확히 나오는지"만 스크립트 하나로 확인하는 실험입니다.
결과는 "되는지"가 아니라 **필드별 정답률 표**로 남깁니다. (PM 흐름 문서 8절 평가 방식: 영수증 N장 기준 필드별 정답률)

- 모델: Claude (`claude-opus-5-5`, 이미지 입력 + JSON 형식 강제)
- 앱 코드와 완전히 분리되어 있어 베이스코드에 영향 없음

## 뽑는 값

| 값 | 쓰이는 곳 |
|---|---|
| 가맹점, 금액, 일시(날짜·시각), 용도 후보 | **U-06 출력 (평가의 주축)** |
| 업종 | U-04 클린카드 제한업종 검사 |
| 시각 | U-04 심야(23시~06시)·공휴일 사용 검사 |
| 카드 뒷 4자리 | 법인카드 여부 확인 |
| 승인번호 | 중복 청구 방지 |
| 품목 | 제한 품목(주류 등) 확인 |

## 절차

### 1. 영수증 사진 모으기 (10장 목표)

`receipts/` 폴더에 jpg·png·webp 로 넣습니다. 파일명은 `r01.jpg`, `r02.jpg` … 처럼 짧게.

- 종류를 섞습니다: 식당, 카페, 편의점, 택시, 주유소, 숙박, 서점 등
- 상태도 섞습니다: 선명한 것, 흐린 것, 구겨진 것, 세로로 긴 것
- **카드번호 앞자리, 이름 등 개인정보는 가리고 찍습니다.** 사진은 깃에 올라가지 않도록 설정되어 있습니다.
- 화면 샘플(`frontend/public/receipts/`)은 이 폴더의 원본에 검은 박스를 씌운 판본입니다. 원본을 바꾸면 마스킹 스크립트(좌표 수동)를 다시 돌려야 하니 사진을 추가할 때는 번호·이름을 가리고 찍는 편이 빠릅니다.

### 2. 정답지 작성

`ground_truth.csv` 에 한 장당 한 줄. 눈으로 보고 직접 적습니다. 이게 있어야 정답률을 잴 수 있습니다.

```
file,merchant,date,time,total_amount,card_last4,purpose
r01.jpg,스타벅스 센텀시티,2026-10-20,14:35,9800,1234,회의비
r02.jpg,GS칼텍스 해운대주유소,2026-10-21,08:12,70000,,주유비
```

- `date` YYYY-MM-DD, `time` HH:MM(24시간), `total_amount` 숫자만
- 모르거나 영수증에 없는 값은 비워 둡니다 (채점에서 제외됨)
- `purpose` 는 다음 중 하나: 식비, 회의비, 교통비, 숙박비, 주유비, 소모품비, 도서비, 경조사비, 기타

### 3. API 키 설정 (처음 한 번)

```bash
cp .env.example .env
```
`.env` 를 열어 `ANTHROPIC_API_KEY=` 뒤에 키를 넣습니다. `.env` 는 깃에 올라가지 않습니다.

> 유료 API입니다. 키 발급에 결제 수단 등록이 필요할 수 있으니 KPC 비용 인정 여부를 먼저 확인하세요.
> 영수증 10장 테스트 비용은 수백 원 수준입니다 (사진 1장당 입력 약 1,500~3,000 토큰).

### 4. 실행

```bash
# 처음 한 번: 가상환경 만들고 설치
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# 비용 확인용으로 2장만 먼저
.venv/bin/python extract_receipts.py extract --limit 2

# 전체
.venv/bin/python extract_receipts.py extract

# 정답지와 비교
.venv/bin/python extract_receipts.py eval
```

### 5. 결과 읽기

- `results/<파일명>.json` 사진 한 장의 추출 결과 전체 (품목, 신뢰도, 메모, 토큰 수 포함)
- `results/summary.csv` 전체를 한 표로
- `eval` 출력: 필드별 정답률과 틀린 항목 목록

```
영수증 10장 기준 필드별 정답률

필드            정답   정답률
merchant        9/10     90%
date           10/10    100%
time            8/10     80%
total_amount   10/10    100%
card_last4      7/10     70%
purpose         8/10     80%
```

## 프론트 화면과 붙여 보기 (server.py)

프론트의 "영수증 등록" 화면(U-06)을 실제 인식으로 돌려보는 임시 서버입니다. 백엔드가 `POST /api/receipt` 를 만들기 전까지만 씁니다.

```bash
# 1) 이 폴더에서 서버 켜기 (API 키는 .env 에서 읽음)
.venv/bin/python server.py
```

```bash
# 2) frontend/.env.local 에 한 줄 적고 dev 서버가 다시 뜨면 헤더가 "백엔드 연결"로 바뀜
echo "VITE_USE_MOCK=false" > ../../frontend/.env.local
```

- 제공 주소는 `POST /api/receipt` 하나뿐이라 다른 탭(규정 Q&A 등)은 오류가 납니다. 정상입니다.
- 사진은 브라우저에서 base64 로 이 서버까지만 오고, API 키는 서버 안에만 있습니다.
- 끝나면 `.env.local` 을 지우면 다시 목업 모드로 돌아갑니다.

## 1차 테스트 결과 (2026-11-03, claude-opus-5-5)

영수증 11장: 카페 3, 식당 2, 베이커리 1, 편의점 1, 우체국 1, 백화점 1, 온라인 쇼핑 1, 저화질·잘린 사진 1.
최근 영수증 6장은 팀원이 직접 찍은 것, 나머지 5장은 인터넷의 오래된 샘플(2011~2023년)을 섞었다.
카드번호가 가려진 영수증은 `card_last4 = null` 이 정답이다.

| 필드 | 정답 | 정답률 |
|---|---|---|
| merchant (가맹점) | 11/11 | 100% |
| date (날짜) | 11/11 | 100% |
| time (시각) | 11/11 | 100% |
| total_amount (합계) | 11/11 | 100% |
| card_last4 (카드 뒷4자리) | 11/11 | 100% |
| purpose (용도 후보에 정답 포함) | 11/11 | 100% |

- 토큰: 입력 38,611 / 출력 4,838 (장당 평균 입력 3,510, 출력 440). 소요 시간 장당 3.7~9.1초, 평균 약 5.9초.
- 비용: 콘솔 사용량 기준으로 11장에 1달러 미만. 10장 단위 테스트를 여러 번 반복해도 5달러 크레딧 안에서 충분하다.
- 신뢰도: 10장 `high`, 저화질·잘린 사진 1장만 `medium`. 이 한 장도 값은 모두 맞았고, notes 에 "왼쪽이 잘려 연도 앞자리를 추정했다"고 스스로 적었다.
- 잘한 점: 공급가액+부가세=합계 검산을 스스로 하고, 현금 영수증의 거래번호를 승인번호로 잘못 넣지 않았으며, 명품 구매 건은 "업무 용도 불분명, 사람 확인 필요"라고 notes 에 남겼다.
- 한계: 11장 모두 비교적 선명한 정면 사진이라 흐림·구김·그림자 사례가 부족하다. 용도 후보는 2~3개를 주므로 최종 선택은 사용자가 해야 한다.

앱에 넣을 때의 제안 (U-06):
1. 추출값을 지출 건 생성 폼에 미리 채우고, 사용자가 고쳐서 저장하게 한다.
2. `confidence` 가 `medium` 이하이거나 notes 에 "추정"이 있으면 해당 칸에 노란 표시를 하고 "담당자 확인 필요" 로 넘긴다.
3. 용도 후보 첫 번째를 기본 선택으로 두되 드롭다운으로 바꿀 수 있게 한다.
4. 카드 뒷 4자리는 대부분 가려져 있으므로 필수 입력으로 두지 않는다.
