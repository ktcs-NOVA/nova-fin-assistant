# 회계 관리자 화면 구성안

작성: 박철환 (프론트엔드/UI) · 2026-11-09
PM 우선순위 표(꼭 하기 / 여유 있으면 / 빼기)와 코치 피드백("경비 처리가 메인")을 반영해, 회계 관리자 화면을 어떻게 구성할지 정리한 문서입니다. 구현 전 합의용이며, 확정되면 `API.md`와 와이어프레임 문서를 갱신합니다.

---

## 1. 한 줄 방향

**메뉴를 늘리지 않고, 지금 있는 "정산 검토(M-01)" 한 흐름을 두껍게 만든다.**

관리자 화면은 "직원이 정산을 올림 → AI가 판정·계정과목을 확인 → 관리자가 승인/반려 → 직원이 반려 이유를 보고 고침 → 안 올린 사람은 관리자가 챙김" 이 한 줄로 설명되게 구성합니다. 나머지 기능(세무·결산·감사·예산 등)은 메뉴에 두지 않고 결과보고서의 확장 로드맵으로 넘깁니다.

## 2. 현재 상태

| 항목 | 상태 |
|---|---|
| 관리자 메뉴 | `정산 검토` 1개 (목록 → 상세) |
| 목록 화면 | 요약 숫자 3개, 판정·상태 필터, 표 30건, 보완 필요 우선 정렬 |
| 상세 화면 | 6단계 스테퍼, 제출 정보, AI 판정 카드(U-04 재사용), 반려 사유 체크 → 메시지 초안 → 승인/반려, 직원 안내 미리보기(U-09) |
| 데이터 | 전부 목업 (`frontend/src/mocks/submissions.json` 30건: 국내출장 9 · 법인카드 13 · 업무추진비 8) |
| 백엔드 | **관리자 API 없음.** 제출 내역 저장 테이블도 없음. 직원 기능(Q&A·검증·출장비·결의서·절차)만 있음 |
| 역할 전환 | 헤더 버튼으로 직원/관리자 전환 (시연용, 로그인 없음) |
| 재사용 가능한 재료 | U-04 판정 엔진, U-07 계정과목 제안(`suggest_account`), RAG 문서 구분(`audience`) + 관리자용 회계·예산·자금 규정 7종(11/9 추가) |

## 3. 범위 (PM 우선순위 표 반영)

| 구분 | ID | 기능 | 관리자 화면에서 어떻게 |
|---|---|---|---|
| **꼭 하기** | M-01 | 검토 대기함 + 반려 작성 | 지금 화면을 완성형으로. 코칭 1·2번(반려 해석, 미신청자 알림)을 여기에 붙임 |
| 여유 있으면 | M-05 | 계정과목 오분류 검토 | 별도 메뉴 없이 **M-01 상세 안의 카드 1개**. 직원 입력 vs AI 제안 비교, 불일치면 경고 |
| 여유 있으면 | M-02 | 회계처리 기준 Q&A | 직원 Q&A 화면 재사용, 문서 범위만 관리자용(`audience: admin`) |
| 빼기 | M-03 | 세무 일정 | 메뉴 없음. 회의에서 재논의 |
| 빼기 | M-04, M-06~M-09 | 결산·감사·예산·문의 분석·점검 리포트 | 메뉴 없음. 결과보고서 "확장 로드맵" 표에만 기재 |

껍데기 메뉴를 두지 않는다는 기존 결정(와이어프레임 문서 2절)은 유지합니다.

## 4. 화면 구성

```
회계 관리자
├─ 정산 검토 (홈)            M-01 목록 + 여비 미신청 알림 띠
│   └─ 정산 검토 상세         M-01 상세 + 계정과목 검토 카드(M-05) + 직원 안내 미리보기(U-09)
├─ 출장 여비 미신청           코칭 2번 (회의 후 확정)
└─ 회계 Q&A                  M-02 (여유 있으면)
```

### 4-1. 정산 검토 (홈) — M-01 목록, 기존 화면 보강
- 맨 위 **알림 띠**: `여비 미신청 출장자 N명 (기한 임박 n · 초과 m)` → 누르면 4-2 화면. 코칭 2번이 들어갈 자리.
- 요약 숫자에 `오늘 처리` 1개 추가. 필터·표·정렬은 그대로.

### 4-2. 출장 여비 미신청 — 코칭 2번 (회의 후 확정)
- 출장 신청 목록과 정산 제출 목록을 대조해 "출장은 끝났는데 여비 정산이 없는 사람"을 표로.
- 컬럼: 출장자 · 부서 · 출장 기간 · 완료일 · 정산 기한(완료일 + 15일, 여비규정 제3조의2) · 남은 일수 · 상태(임박/초과).
- 행마다 `안내 메시지 보내기` (초안 생성만, 실제 발송 없음).
- 새 목업 데이터 필요: `trips.json` (출장 신청 20건 안팎, 일부는 제출 내역과 짝이 맞게).

### 4-3. 정산 검토 상세 — 기존 상세에 카드 추가
- **계정과목 검토 카드 (M-05)**
  - `직원 입력: 소모품비` / `AI 제안: 회의비 (근거: …)` 를 나란히 표시.
  - 불일치면 노란 경고 + 반려 사유 후보에 `계정과목 재확인` 항목 자동 추가.
  - 데이터: 제출 건에 `account` 칸 1개 추가. 제안은 기존 `POST /api/voucher-draft` 호출로 받음 → **백엔드 추가 없음**.
- **직원에게 보이는 안내 (U-09)**
  - 미리보기는 지금처럼 유지. 반려 후 직원 화면 `내 제출 내역`에서 같은 내용이 보이게 하는 것은 코칭 1번이라 회의 후.

### 4-4. 회계 Q&A — M-02 (여유 있으면)
- 직원 `규정 Q&A`와 같은 화면, 제목만 `회계처리 기준 Q&A`, 요청에 `audience: admin`.
- 11/9 추가한 회계규정·시행세칙·예산·자금 규정이 검색 대상이 되어 "선금 지급 조건", "대손처리 요건" 같은 질문에 조항 근거가 나옴.
- 백엔드: Q&A 요청 스키마에 `audience` 선택 필드 1개 추가 필요 (검색기는 이미 지원).

### 4-5. 권한 분리 — 코칭 3번 (회의 후 확정)
- 위 구조 위에 `/employee/*`, `/admin/*` 주소와 역할 선택 첫 화면을 씌우는 작업.
- 회의에서 확정되면 어느 단계에서든 붙일 수 있음. 현재 헤더 전환 버튼은 그때까지 유지.

---

## 5. 시연 동선 (한 줄)

1. 직원이 영수증 등록 → 청구 검증 → 제출
2. 관리자 홈에 새 건 + 미신청 알림 띠
3. 상세에서 AI 판정 · 계정과목 불일치 확인 → 반려 사유 체크 → 메시지 초안 → 반려
4. 직원 `내 제출 내역`에서 반려 이유와 수정 방법 확인 (회의 후)
5. 관리자가 미신청자에게 안내 (회의 후)

## 6. 백엔드에 요청할 것 (`API.md` 추가 예정)

| 용도 | 주소 | 비고 |
|---|---|---|
| 제출 내역 목록 | `GET /api/admin/submissions` | **구현 완료 (11/9)** + 직원 제출 `POST /api/submissions` |
| 제출 내역 상세 | `GET /api/admin/submissions/{id}` | 구현 완료 (11/9) |
| 승인/반려 저장 | `POST /api/admin/submissions/{id}/decision` | 구현 완료 (11/9) |
| 반려 메시지 초안 | `POST /api/admin/submissions/{id}/reject-draft` | 구현 완료 (11/9), LLM 다듬기 포함 |
| 여비 미신청 출장자 | `GET /api/admin/unclaimed-trips` | 코칭 2번 확정 시 |
| 회계 Q&A | `POST /api/qa` 에 `audience` 선택 필드 | M-02 |
| 계정과목 검토 (M-05) | 추가 없음 | 기존 `POST /api/voucher-draft` 사용 |
