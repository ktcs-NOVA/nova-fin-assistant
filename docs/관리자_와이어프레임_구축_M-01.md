# 관리자 와이어프레임 구축 (M-01)

작성: 박철환 (프론트엔드/UI) · 2026-11-02
기능명세서의 회계 관리자 계정 **M-01**과, 그에 딸린 직원 측 **U-09**를 눌러볼 수 있는 화면으로 만든 것입니다. 데이터는 전부 목업이며, 백엔드가 붙으면 API 모듈의 스위치만 바꿔 연결합니다.

## 3. 화면 구성

### 로그인 (첫 화면)
- 직원 3명(노은비·박철환·황종원)과 회계 관리자 1명(이채은) 중 하나를 고름. 비밀번호 없음.
- 직원을 고르면 직원 메뉴 5개, 관리자를 고르면 `정산 검토` 하나로 진입. 안에서는 역할을 바꿀 수 없고 헤더의 `로그아웃`으로 돌아옴.
- 고른 계정은 브라우저에 기억되고, 모든 API 요청에 사번 헤더로 실려 체크리스트 등이 사람별로 구분됨.

### 헤더
- 오른쪽에 로그인한 계정 칩 `역할 · 이름 · 로그아웃`.
- `목업 모드` 뱃지. 가짜 데이터로 동작 중이라는 표시. 백엔드 연결 시 `백엔드 연결`로 바뀜.

### 정산 검토 대기함 (목록) — M-01
- 요약 숫자: 제출 / 검토 대기 / 확인 필요 건수
- 필터: 판정(확인 필요·전체·판정별), 상태(검토 대기·전체·승인·반려). 기본값은 "검토 대기 중 확인 필요한 건"
- 표: 제출일, 제출자, 부서, 유형, 내용, 금액, AI 판정, 문제 항목(걸린 규정 항목명), 상태
- 정렬: 보완 필요 → 담당자 확인 필요 → 규정상 확인 가능, 같은 판정 안에서는 제출일 순
- 행 클릭 → 상세

### 정산 검토 상세 — M-01
1. 6단계 스테퍼 (검토 대기 건은 5단계, 처리 완료 건은 6단계)
2. 제출 정보: 내용, 제출자·부서, 유형, 사용일시, 사용처, 금액, 제출일, 종합 판정, 상태
3. AI 사전검증 결과: 항목별 결과 카드 (U-04와 동일 컴포넌트)
4. 검토 패널
   - 왼쪽 "반려 사유 선택": AI가 찾은 문제 항목이 체크박스로 나열, 기본 전부 체크
   - `근거 기반 반려 메시지 초안 생성` → 오른쪽 메시지 칸 채움 (실제는 백엔드 RAG, 지금은 목업)
   - 오른쪽 "반려 메시지": 자유 수정 가능
   - `반려` / `승인` 버튼. 사람이 누르고 확인 창을 거침. 반려는 메시지가 있어야 가능
5. 직원에게 보이는 안내 (미리보기) — U-09: 초안이 있을 때만 표시

처리가 끝난 건(승인·반려)은 검토 패널 대신 처리 결과와 메시지를 읽기 전용으로 보여줌.

## 4. 목업 데이터

`frontend/src/mocks/submissions.json` — 가상 제출 내역 30건
- 유형: 국내출장 9 / 법인카드 13 / 업무추진비 8
- 판정: 보완 필요 17 / 담당자 확인 필요 4 / 규정상 확인 가능 9
- 상태: 검토 대기 24 / 승인 4 / 반려 2
- 문제 항목의 근거는 전부 한국해양진흥공사 규정 (여비규정, 법인카드 관리 및 사용 지침, 업무추진비 및 조직관리비 집행 지침, 별표 1)
- 유형에 맞는 문제 항목만 붙음 (출장 건에는 여비 규정, 카드 건에는 카드 지침 등)
- 백엔드 목업 응답으로 그대로 사용 가능

## 5. 백엔드에 필요한 API (API 모듈에 주소까지 정의됨)

| 함수 | 방식 | 주소 | 용도 |
|---|---|---|---|
| listSubmissions | GET | /api/admin/submissions | 목록 |
| getSubmission | GET | /api/admin/submissions/{id} | 상세 |
| decideSubmission | POST | /api/admin/submissions/{id}/decision | 승인/반려 저장 (`decision`, `message`) |
| draftRejectMessage | POST | /api/admin/submissions/{id}/reject-draft | 선택한 문제 항목(`issue_fields`)으로 RAG 근거 기반 반려 메시지 초안 생성 → `{ message, sources[] }`. `extra_issues[]`(선택)는 AI 판정 밖의 추가 사유로, M-05 계정과목 불일치가 `{ field, verdict, message, basis, fix }` 모양으로 들어옴 |
| suggestAccount (M-05) | POST | /api/voucher-draft | 기존 U-07 API. 제출 건을 청구 내역 모양으로 바꿔 보내고 `lines[]`의 과목·세목·확인 수준·근거를 읽음 |

응답 모양은 `submissions.json`의 한 건과 같음. 제출 건에 `account`(직원이 결의서에 적은 계정과목, 선택) 필드가 추가됨.

## 6. 가정한 것 (PM 확인 필요)

- 반려된 건은 직원에게 돌아가고, 직원이 수정해 다시 제출한다.
- 검토자와 예산 담당은 같은 사람이다 (M-07 예산 화면을 만들 경우 같은 역할 아래 둠).
- 관리자 승인 시 6단계 예산 반영은 자동으로 넘어간다 (화면에서는 스테퍼만 6으로 이동).
